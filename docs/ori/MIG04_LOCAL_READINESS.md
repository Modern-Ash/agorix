## Required implementation before pilot

1. Provision a dedicated Agorix PostgreSQL database, take and verify a SQLite backup, and migrate the account/project/link tables without changing ownership IDs or revisions. Compare row counts and project hashes before cutover. Switch the project service to PostgreSQL only after a rollback plan is rehearsed. The production policy and project write must use the same database. The adapter's presence alone is not cutover evidence.
2. Bind the Tutor API's proposal, decision and apply routes to a trusted account session and project owner lookup, same-origin/CSRF checks, rate limits, and server-derived evidence. The browser supplies only opaque ticket and learner choice.
3. In the same durable transaction as an accepted project update, check expected project revision, policy epoch, pilot mode, human authorization, kill switch and a project allowlist with the server-resolved owner. Reject without a write on any mismatch. Keep the existing audit and aggregate telemetry boundaries.
4. Exercise two-connection races, duplicate tickets, rollback before and after a commit, service restart and database failure; then run a real-process rollback drill. Only the one reviewed project may be allowlisted. Confirm anonymous Kids remains playable when the kill switch is on.
5. After the account and project exist, record the human pilot authorization in the policy store and enable the route. Verify from the WebApp. Emergency disable must increment the policy epoch durably before it reports success.
