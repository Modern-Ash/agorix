# Studio visual capability matrix

Issue #1652, under epic #1648. This matrix describes the current Studio Workbench. The shared program and runtime support more nodes than the Workbench can currently create. A block appears in the palette only when Studio has an insertion path that reaches a canonical edit.

The first complete visual journey is: insert `if` → choose a sensing or comparison reporter → click or drop it into the condition socket → adjust numeric operands where present → Run/Step → inspect deterministic evidence. An invalid reporter, stale program hash, missing `if`, invalid operand, or rejected canonical program leaves accepted state unchanged.

Comparison reporter journey: insert `if` or `repeat until` → choose <, >, ≤, ≥ or = → set either side to Number, a declared Variable, a declared List length, X position or Y position → choose a declaration where needed → Run/Step → inspect canonical code and runtime evidence. Unknown declarations, malformed sources, unsupported sides and numeric edits to nonliteral operands are refused before canonical mutation.

Variable journey: create `energy` → insert Set variable → choose `energy` → enter a value → Run/Step → inspect the watcher and code projection. Duplicate names, unknown references, non-finite values and stale edits are refused before accepted state changes.

Actor journey: open Scene → create `Robot` → select its card → add a Move block → Run/Step → inspect Robot in the deterministic stage and code projection. Actor and script are saved in one project transaction; legacy actors receive explicit ownership of their existing scripts before the new actor is added.

Asset journey: insert Switch costume, Switch backdrop or Play sound → choose a known project asset directly on the block → Run/Step → inspect the deterministic stage and sound evidence. Unknown asset ids are refused by the host; image previews accept only bundled art or bounded PNG/WebP data.

Image creation journey: open Scene → choose costume or backdrop → import a PNG/WebP under 60 KB or draw on the canvas → save → select the new thumbnail. The protocol and host reject remote URLs, other image formats and oversized data before project metadata changes.

Event journey: select an actor → create a script triggered by message `go` → select that script header → add blocks → add a Broadcast `go` block to another script → Run/Step → inspect deterministic execution. Unknown actor ids and stale program hashes refuse script creation without changing accepted state.

Key/click script journey: select an actor in Scene → choose When key pressed and a key, or When actor clicked → create the script → select its header → add blocks → inspect the canonical code. The protocol rejects missing keys, unexpected trigger fields and stale hashes. Focus the stage and press the selected key, or click the actor → inspect deterministic stage frames and event evidence. The stage ignores unsupported keys; the protocol rejects unsupported key bindings and malformed actor ids. The learner can focus the capture button and press a supported key, then see it selected before creating the script.

Script removal journey: select an actor's script in Build → choose Delete script on its header → confirm deletion → inspect the remaining canonical program and actor ownership. The host rejects a stale hash, a script owned by another actor, and removal of the final project script without changing accepted state. The learner may create a new script for an actor whose last script was removed.

List journey: create `inventory` in Blocks → insert Add to list or Insert at index → choose a declared list → edit item value and index → Run/Step → inspect canonical code, runtime trace and the stage list watcher. The watcher displays the runtime items only when the declaration is visible; a bounded scroll area keeps large lists usable. Duplicate names, unknown list references, invalid numeric inputs and stale hashes are refused without changing accepted state.

Initial list journey: create `inventory` in Blocks → expand its declaration → add, edit or remove numeric initial items → Run/Step → inspect canonical code and runtime behavior. A list can hold up to 100 items, each between −1,000,000 and 1,000,000. Unknown list ids, malformed values and stale edits are refused before canonical mutation.

Numeric reporter journey: declare `energy` and `inventory` → add a list or variable operation → choose Number, Variable, List length, List item, X position, Y position, Distance to actor or arithmetic (+, −, ×, ÷) in a numeric socket → select the declaration, item index or actor when needed → Run/Step. Unknown references, unsupported sockets, invalid indices and stale edits are refused before canonical mutation. Arithmetic and random operands accept a literal, declared variable, list length, position sensor or distance to a known actor; a second arithmetic level is editable; deeper operations remain visible until recursive editing lands.

Random and remainder journey: add Set variable or Add to list → choose Remainder, Random number or Random integer as the numeric source → edit left/right or minimum/maximum literal values → Run/Step → inspect code and runtime evidence. Non-finite edits and unsupported operand paths are refused before canonical mutation; a second arithmetic level can be composed and edited; deeper operations remain visible by name.

Condition-detail journey: insert `if` → choose Boolean literal or Touching character → set False or select a project actor → Run/Step → inspect deterministic evidence. The host rejects unknown actor ids and stale edits before canonical mutation; replacing a contact condition uses a known actor from the scene.

Logical journey: insert `if` or `repeat until` → choose And, Or or Not from the palette → place it in the condition socket → choose Goal contact, Stage edge contact or Boolean literal for each operand → set a literal to True or False → Run/Step → inspect canonical code and runtime evidence. Malformed operands and unsupported sides are refused before canonical mutation.

Sensor journey: add Set variable or Add to list → choose X position, Y position or Distance to actor as the numeric source → choose a known actor for distance → Run/Step → inspect canonical code and deterministic runtime evidence. Unknown actor ids are rejected by the host before accepted state changes.

Arithmetic journey: add Set variable or Add to list → choose Add, Subtract, Multiply or Divide as the numeric source → edit the two literal operands → Run/Step → inspect canonical code and runtime evidence. Non-finite values and unsupported operand paths are rejected before accepted state changes; an existing nonliteral operand is shown by name without replacing it.

Declaration watcher journey: set a variable initial value or edit list initial items → toggle Show on stage → Run/Step → inspect the stage watcher. Hidden declarations remain in the canonical program and retain their values; invalid values, unknown ids and stale edits are refused before mutation.

Actor removal journey: select an actor in Scene → choose Delete selected actor → review the actor name and owned script count → confirm → inspect remaining actors and canonical scripts. The host refuses stale hashes, changed ownership, references from surviving scripts, and removal of the final actor or script without a project write.

Keyboard nesting journey: place a Move block after Repeat or If → focus Move → press Alt+Right to put it inside the preceding body/Then branch, or Alt+Shift+Right for Else → press Alt+Left to move it out. Focus follows the block after the canonical workspace update. At a list edge or without a preceding compatible control, Studio announces why no move happened and leaves the program unchanged.

Layer journey: create two overlapping actors → add Go to front or back layer to an actor script → choose Front or Back on the block → Run/Step → inspect the deterministic stage order. Unknown layer values and stale edits are refused without changing the canonical program.

Arithmetic operand journey: create `score` and `inventory` → set a variable to Add or Random integer → choose Variable, List length, X/Y position or Distance to actor for either operand → choose a declared reference when needed → Run/Step and inspect the result. Unknown declarations, actors, sides and stale edits are refused before accepted state changes.

Two-level arithmetic journey: set `score` to Add → choose Multiply for the left operand → edit its two numeric values inside the block → Run/Step and inspect the canonical code and runtime result. Invalid paths, nonliteral values and stale edits are refused before accepted state changes.

Costume drop journey: open Scene → drag a known costume thumbnail onto a visible stage actor → inspect its updated costume immediately and after Run/Step. Dropping an unknown costume or a backdrop on an actor is ignored; the host also rejects an unknown costume id before metadata persistence. Clicking a costume for the selected actor remains the keyboard-accessible path.

Backdrop drop journey: open Scene → drag a known backdrop thumbnail onto the stage → inspect the rendered backdrop before and after Run/Step. Unknown backdrop ids and other asset kinds are ignored by the drop target and refused by the host before metadata persistence; choosing a backdrop by click remains keyboard accessible.
