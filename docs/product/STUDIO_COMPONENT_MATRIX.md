The first complete visual journey is: insert `if` → choose a sensing or comparison reporter → click or drop it into the condition socket → adjust numeric operands where present → Run/Step → inspect deterministic evidence. An invalid reporter, stale program hash, missing `if`, invalid operand, or rejected canonical program leaves accepted state unchanged.

Numeric reporter palette journey: create a variable or list, then insert Set variable or Add to list → choose Number, a declared Variable, List length/item, X/Y position, Distance to actor, arithmetic, remainder or random from the visual palette → click its highlighted value socket or drag the reporter onto it → edit its typed fields → Run/Step → inspect canonical code and deterministic evidence. Palette entries requiring a declaration or actor appear only when that target exists. Dropping a statement or an unsupported expression on a numeric socket leaves the canonical program unchanged. The socket's source menu remains the keyboard-accessible alternative.

Math function journey: insert Set variable → choose Math function from the palette or numeric source menu → place it in the value socket → choose Absolute value, Round, Round down or Round up → edit the literal operand or choose a declared variable, list length, position or actor distance as its source → Run/Step → inspect the canonical code and deterministic result. The function selector preserves an existing nonliteral operand without replacing it; unknown references, malformed functions, non-finite numbers, stale program hashes and incompatible targets are refused before accepted state changes.

Comparison reporter journey: insert `if` or `repeat until` → choose <, >, ≤, ≥ or = → set either side to Number, a declared Variable, a declared List length or Item, Random integer, Math function, X position, Y position or Distance to actor → choose a declaration or target actor and edit the item index, random bounds or math function and its literal where needed → Run/Step → inspect canonical code and runtime evidence. The VSIX protocol carries those visible nested edits to the canonical host. Unknown declarations, malformed sources, unsupported sides and numeric edits to nonliteral operands are refused before canonical mutation.

Variable journey: create `energy` → insert Set variable → choose `energy` → enter a value → Run/Step → inspect the watcher and code projection. Duplicate names, unknown references, non-finite values and stale edits are refused before accepted state changes.

Actor journey: open Scene → create `Robot` → select its card → add a Move block → Run/Step → inspect Robot in the deterministic stage and code projection. Actor and script are saved in one project transaction; legacy actors receive explicit ownership of their existing scripts before the new actor is added.

Asset journey: insert Switch costume, Switch backdrop or Play sound → choose a known project asset directly on the block → Run/Step → inspect the deterministic stage and sound evidence. Unknown asset ids are refused by the host; image previews accept only bundled art or bounded PNG/WebP data.

Sound import journey: open Scene → Sounds → name and import a PCM WAV under 60 KB and at most five seconds → preview locally → insert Play sound and select the new sound on its visual block → Run/Step → inspect deterministic sound evidence → reopen the same portable project in Web. The project does not fetch remote audio. A malformed WAV, oversized file or unsupported source is refused before metadata changes. Exporting learner-added media outside the local project requires the existing explicit adult opt-in.

Visual debugging journey: mark a statement block with a breakpoint → Play → Studio pauses on the corresponding deterministic runtime frame, with the block highlighted → resume or Step. In Evidence, choose a declared variable from the closed list to see its observed value history, and optionally pause when its value changes. A missing variable or unmarked block never triggers a pause; duplicate frames never create duplicate history points. Breakpoints and watches are local presentation state and never change the canonical program or travel with its portable file.

Pre-play review journey: insert a `repeat until` with a condition that may change and no wait → Studio shows a finding card before Play → choose Inspect block to focus it or ask Ori for a local counts-only explanation → add a wait or remove the loop and the card disappears. A structurally false condition is reported separately as a loop that cannot exit. A condition that is already true, or a body that may wait through a custom block, is not flagged. The same review surface also shows shared writes from scripts activated by one event and conservative runtime-budget estimates for current scripts (the program model does not yet represent actor copies), with Inspect actions for both sides of a shared write. These findings are advisory; only a run can prove observed behavior.

Image creation journey: open Scene → choose costume or backdrop → import a PNG/WebP under 60 KB or draw on the canvas → save → select the new thumbnail. The protocol and host reject remote URLs, other image formats and oversized data before project metadata changes.

Event journey: select an actor → create a script triggered by message `go` → select that script header → add blocks → add a Broadcast `go` block to another script → Run/Step → inspect deterministic execution. Unknown actor ids and stale program hashes refuse script creation without changing accepted state.

Key/click script journey: select an actor in Scene → choose When key pressed and a key, or When actor clicked → create the script → select its header → add blocks → inspect the canonical code. The protocol rejects missing keys, unexpected trigger fields and stale hashes. Focus the stage and press the selected key, or click the actor → inspect deterministic stage frames and event evidence. The stage ignores unsupported keys; the protocol rejects unsupported key bindings and malformed actor ids. The learner can focus the capture button and press a supported key, then see it selected before creating the script.

Script removal journey: select an actor's script in Build → choose Delete script on its header → confirm deletion → inspect the remaining canonical program and actor ownership. The host rejects a stale hash, a script owned by another actor, and removal of the final project script without changing accepted state. The learner may create a new script for an actor whose last script was removed.

List journey: create `inventory` in Blocks → insert Add to list or Insert at index → choose a declared list → edit item value and index → Run/Step → inspect canonical code, runtime trace and the stage list watcher. The watcher displays the runtime items only when the declaration is visible; a bounded scroll area keeps large lists usable. Duplicate names, unknown list references, invalid numeric inputs and stale hashes are refused without changing accepted state.

Initial list journey: create `inventory` in Blocks → expand its declaration → add, edit or remove numeric initial items → Run/Step → inspect canonical code and runtime behavior. A list can hold up to 100 items, each between −1,000,000 and 1,000,000. Unknown list ids, malformed values and stale edits are refused before canonical mutation.

Numeric reporter journey: declare `energy` and `inventory` → add a list or variable operation → choose Number, Variable, List length, List item, X position, Y position, Distance to actor or arithmetic (+, −, ×, ÷) in a numeric socket → select the declaration, item index or actor when needed → Run/Step. Unknown references, unsupported sockets, invalid indices and stale edits are refused before canonical mutation. Arithmetic and random operands accept a literal, declared variable, list length, position sensor or distance to a known actor; a third arithmetic level can be composed through typed source choices and its literal fields edited; arbitrary-depth source editing remains pending.

Random and remainder journey: add Set variable or Add to list → choose Remainder, Random number or Random integer as the numeric source → edit left/right or minimum/maximum literal values → Run/Step → inspect code and runtime evidence. Non-finite edits and unsupported operand paths are refused before canonical mutation; a third arithmetic level can be composed through typed source choices and its literal fields edited; arbitrary-depth composition remains pending.

Condition-detail journey: insert `if` → choose Boolean literal or Touching character → set False or select a project actor → Run/Step → inspect deterministic evidence. The host rejects unknown actor ids and stale edits before canonical mutation; replacing a contact condition uses a known actor from the scene.

Logical journey: insert `if` or `repeat until` → choose And, Or or Not from the palette → place it in the condition socket → choose Goal contact, Stage edge contact, Actor contact, Boolean literal or a numeric comparison for each operand → select the target actor, set a Boolean literal, or choose numeric sources and edit literals, list indices, random bounds or a math function inside the comparison → Run/Step → inspect canonical code and runtime evidence. The VSIX protocol accepts these visible controls and rejects malformed references, numbers and sides before the host. Malformed operands and unsupported sides are refused before canonical mutation.

Sensor journey: add Set variable or Add to list → choose X position, Y position or Distance to actor as the numeric source → choose a known actor for distance → Run/Step → inspect canonical code and deterministic runtime evidence. Unknown actor ids are rejected by the host before accepted state changes.

Arithmetic journey: add Set variable or Add to list → choose Add, Subtract, Multiply or Divide as the numeric source → edit the two literal operands → Run/Step → inspect canonical code and runtime evidence. Non-finite values and unsupported operand paths are rejected before accepted state changes; an existing nonliteral operand is shown by name without replacing it.

Declaration watcher journey: set a variable initial value or edit list initial items → toggle Show on stage → Run/Step → inspect the stage watcher. Hidden declarations remain in the canonical program and retain their values; invalid values, unknown ids and stale edits are refused before mutation.

Actor removal journey: select an actor in Scene → choose Delete selected actor → review the actor name and owned script count → confirm → inspect remaining actors and canonical scripts. The host refuses stale hashes, changed ownership, references from surviving scripts, and removal of the final actor or script without a project write.

Keyboard nesting journey: place a Move block after Repeat or If → focus Move → press Alt+Right to put it inside the preceding body/Then branch, or Alt+Shift+Right for Else → press Alt+Left to move it out. Focus follows the block after the canonical workspace update. At a list edge or without a preceding compatible control, Studio announces why no move happened and leaves the program unchanged.

Layer journey: create two overlapping actors → add Go to front or back layer to an actor script → choose Front or Back on the block → Run/Step → inspect the deterministic stage order. Unknown layer values and stale edits are refused without changing the canonical program.

Arithmetic operand journey: create `score` and `inventory` → set a variable to Add or Random integer → choose Variable, List length, X/Y position or Distance to actor for either operand → choose a declared reference when needed → Run/Step and inspect the result. Unknown declarations, actors, sides and stale edits are refused before accepted state changes.

Two-level arithmetic journey: set `score` to Add → choose Multiply, Remainder, Random, Random integer or Math function for the left operand → edit its two numeric values, minimum/maximum, or function and literal value inside the block → Run/Step and inspect the canonical code and runtime result. Invalid paths, nonliteral values and stale edits are refused before accepted state changes.

Costume drop journey: open Scene → drag a known costume thumbnail onto a visible stage actor → inspect its updated costume immediately and after Run/Step. Dropping an unknown costume or a backdrop on an actor is ignored; the host also rejects an unknown costume id before metadata persistence. Clicking a costume for the selected actor remains the keyboard-accessible path.

Backdrop drop journey: open Scene → drag a known backdrop thumbnail onto the stage → inspect the rendered backdrop before and after Run/Step. Unknown backdrop ids and other asset kinds are ignored by the drop target and refused by the host before metadata persistence; choosing a backdrop by click remains keyboard accessible.

Stage transform journey: select a visible actor on the idle stage → drag it with a mouse or touch pointer to preview its bounded position, then release to commit one explicit metadata edit; cancel the gesture to restore its prior location. Alt+Arrow also places it (Shift moves ten steps). Use the on-stage direction and size sliders to preview a transform and commit on release or key completion; cancel restores the prior appearance. The rotate/size buttons remain available for discrete keyboard or click adjustments. Inspect the actor and code/runtime after Run or Step. Placement and transform controls are unavailable while execution is running.

Image remix journey: open Costumes or Backdrops → choose Duplicate on an existing image → inspect the new editable draft and name → fill a connected area, flip horizontally or rotate 180° → undo an edit if needed → save explicitly after the source image loads → choose or drag the new thumbnail. The draft does not alter the source asset; bounded PNG/WebP validation still gates persistence.

Image loading journey: duplicate or edit an existing image → wait for its source art to appear on the canvas → save the new draft. Save and drawing actions are unavailable while loading; failed or superseded loads cannot silently replace the draft with a blank image.

Shape drawing journey: open a new or existing costume/backdrop draft → select Line, Rectangle or Ellipse → drag on the canvas to preview the shape → release to keep it, or cancel the pointer to restore the previous image → Undo to remove the completed shape → save explicitly. The original asset remains unchanged until saving the draft.

Gallery journey: open Scene → Costumes or Backdrops → filter by category or search name/tags → choose a bundled image for the selected actor or stage, or drag its thumbnail onto the visual stage → insert a Switch costume/backdrop block that references the chosen asset → Run/Step and inspect the deterministic stage. Filters change only the visible list; they do not mutate project metadata or the canonical program.

Character-from-costume journey: open Scene → choose + Character beside the stage to reveal the full unfiltered costume gallery → choose Add as character on a visual costume card → inspect the newly selected actor with that costume and its own empty start script → add blocks and Run/Step. The same gallery remains reachable through the Costumes tab. The host validates the costume ID before committing actor metadata and the canonical script together; an unknown ID leaves both unchanged.

Custom block call journey: open a project whose selected script already defines a procedure → choose Call custom block from the visual palette → choose a procedure by name on the inserted block → Run/Step and inspect its canonical trace. A script without procedures hides that palette entry. Insertion into another script, a missing procedure id or a stale hash is rejected before accepted state changes. Studio can also create a definition from the selected script’s last 1–20 blocks, rename it, and delete it through a second explicit action that inlines calls. Invalid names, limits, recursive inlining, unknown ids and stale hashes refuse the edit without changing accepted state. The project-wide My blocks list shows definitions from every script immediately after creation or project reopen; selecting one opens the owning actor, script and visual body together. Add or change blocks and nested branches, then return to the script; Run/Step and Web reopen use the same canonical program. The webview protocol preserves bounded procedure definitions in workspace snapshots and rejects malformed or oversized bodies. A missing procedure or an edit that empties its required body is refused.
