# Ori + Agorix: cross-repository process smoke test

This optional test runs the **actual Ori reference HTTP process** from a separate local checkout and calls it through the Agorix consumer transport. It is not a production deployment or a test with children.

## Preparation

Check out `Modern-Ash/ori` and `Modern-Ash/agorix` in separate directories. The Ori checkout must contain `examples/shadow-api/serve.mjs` (Ori PR #48). The Agorix checkout must use this feature branch or its eventual integration branch.

```bash
cd /path/to/agorix
pnpm install --frozen-lockfile
ORI_REPO_PATH=/absolute/path/to/ori pnpm exec vitest run apps/tutor-api/src/oriRealProcessSmoke.test.ts
```

The test starts Ori on a random loopback port, posts synthetic metadata, checks the returned `ori/shadow-plan/v1` schema and invokes Agorix's real shadow transport. It then stops the Ori process.

## Safeguards

- Only synthetic mission index, hint level and script count.
- No learner text, identifiers, program source, secrets or LLM.
- No mutation, no UI rendering, no effect on the existing Kids tutor response.
- Without `ORI_REPO_PATH`, the test is skipped. Ordinary CI remains independent.
- No PR from this workstream targets `main` or `development`.

## Remaining limitations

This verifies transport and schema interoperability, not pedagogical effectiveness, child safety, authentication, mission-specific correctness or production readiness. A later review must decide whether to allow plans to influence Kids; default remains shadow-only.

## Reliability hardening

The optional cross-repository test now fails explicitly if `ORI_REPO_PATH` is configured but does not point to a checkout containing Ori's reference server. It also fails immediately if the real Ori producer returns an incompatible plan contract, instead of treating that mismatch as a transient startup error. The spawned process is terminated and awaited, with a forced-stop fallback.

A green default Agorix CI run **does not prove cross-repository interoperability** when `ORI_REPO_PATH` is absent: the optional test is skipped. To claim the two repositories interoperate, run the explicit command above and retain its output and both commit SHAs as evidence.

## Mandatory verification command (this branch)

Use the explicit command below for a **non-skipping** interoperability check:

```bash
cd /path/to/agorix
ORI_REPO_PATH=/absolute/path/to/ori pnpm test:ori:interop
```

The wrapper `scripts/verify-ori-interop.mjs` fails if `ORI_REPO_PATH` is absent, relative, missing, or not a compatible Ori checkout. It then runs only the real-process smoke test with verbose output and propagates the test exit code.

A default `pnpm test` may still skip this optional cross-repository test. **Only a successful explicit invocation with a real Ori checkout is evidence of interoperability.** Capture the command output and both repository commit SHAs in the review.

## Stronger proof in the consumer test

The real-process test now wraps the Agorix transport with an observing fetch adapter and asserts **exactly one transport request and one schema-valid HTTP response**. This avoids a false green result where the transport silently swallows a connection error while the direct producer probe succeeds.

The explicit verifier emits `ORI_INTEROP_VERIFY: PASS` only after the real-process Vitest command exits successfully, otherwise `ORI_INTEROP_VERIFY: FAIL`. This output is not generated by default CI when the optional cross-repository checkout is missing.
