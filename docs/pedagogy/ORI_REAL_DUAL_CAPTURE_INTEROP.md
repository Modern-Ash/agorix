# Ori real-process dual capture — interoperability gate

The mandatory cross-repository `oriRealProcessSmoke.test.ts` now exercises the complete offline capture using the actual Ori reference HTTP process and the authentic deterministic text tutor in the same test.

The test uses a canonical synthetic Kids mission and its starter program, computes actual runtime observations, builds a validated deterministic TutorRequest, and calls `captureOriLiveComparison` against `createOriPlanConsumer` pointed at the live Ori loopback process. It verifies both messages, source-key isolation, non-mutation and explicit unequal-context warnings.

## Interpretation

This is genuine technical interoperability, **not an efficacy experiment**. The deterministic tutor sees the program and runtime; Ori shadow receives only mission index, hint level and script count. The A/B presentation must retain `equalInputContextProven: false` and `eligibleForEfficacyClaim: false`.

The existing CI job checks out the separate Ori repository and runs this smoke without skipping it. No child identifiers, production endpoint, Kids UI or learner program modification are introduced.
