# Ori — real-process blind JSON export interoperability

The mandatory cross-repository interoperability smoke now verifies a complete **in-memory** offline pipeline:

1. Start the actual Ori reference HTTP process from the separate `Modern-Ash/ori` checkout.
2. Execute the authentic Agorix deterministic text tutor on a canonical synthetic Kids starter program and runtime.
3. Capture both messages using the existing dual-producer evaluation function.
4. Serialize educator-facing A/B text separately from the coordinator-only source key.
5. Parse both JSON documents and assert the real Ori hint, source mapping isolation and the explicit unequal-input caveat.

The test does not create persistent files, register routes or enable Kids. It is a technical contract and privacy-boundary check, not evidence that the tutors received identical inputs or that one improves learning outcomes.

Next: an offline-only runner may persist each JSON to separate new files with restrictive permissions, provided the coordinator explicitly controls both destinations. Never include source keys in educator materials.
