# Requirements - Issue #71

## Functional requirements

- `docs/product/MVP.md` MUST define the MVP around the full learner loop: intent, visible code, bounded AI proposal, visible change, learner decision, deterministic execution, evidence-grounded debugging, correction and explanation.
- `docs/product/MVP.md` MUST reject hidden AI-generated solutions as MVP success.
- `docs/product/MVP.md` MUST keep code visibility as an invariant.
- `docs/product/COMPETITIVE_PRINCIPLES.md` MUST explain how Agorix differs from block-first creative environments, block-to-text environments and coding tools with chat assistants.
- `docs/delivery/IMPLEMENTATION_ORDER.md` MUST reconcile #106 into a durable sequence independent agents can follow.
- `docs/delivery/IMPLEMENTATION_ORDER.md` MUST include a dependency diagram.
- `docs/delivery/IMPLEMENTATION_ORDER.md` MUST include a legacy issue mapping table with preserve, extend, supersede, defer or retire dispositions.
- Local/open model support MUST appear in the roadmap while preserving meaningful offline/tutor-unavailable use.

## Constraints

- Do not delete useful legacy work merely because it is no longer first priority.
- Do not let Capacitor, VS Code or platform proofs precede the AI-native vertical slice.
- Do not frame Agorix as a prompt-engineering course or provider-specific product.
