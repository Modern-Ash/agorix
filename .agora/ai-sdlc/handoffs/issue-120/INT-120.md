# Intent interpretation

Deliver GitHub issue #120 by defining and implementing the tablet interaction model for Agorix Web: touch-first action insertion, non-drag editing, reliable reorder, orientation persistence, virtual-keyboard-safe numeric editing, EN/ES resilience and automated coverage.

The work builds directly on #118. The current shell already has a contextual Action Palette, touch-sized run controls, visible Code, and block cards with Move/Turn/Repeat/If insertion. #120 tightens the interaction contract so the First Mission can be completed without drag or desktop assumptions.

## Source facts

- Source issue: https://github.com/Modern-Ash/agorix/issues/120
- Parent epic: #116.
- Direct predecessor: #118 tablet-first shell.
- Design dependency: #117 design system.
- Accessibility context: `docs/product/UX_REQUIREMENTS.md`.
- Required interactions: tap, drag, reorder, long press, bottom sheet/action palette, numeric input, keyboard fallback, orientation changes, virtual keyboard and stylus compatibility where feasible.

## Product intent

Agorix Web should work as a real tablet learning surface. A learner should complete the First Mission using only touch, without requiring drag, hover, mouse precision, or a hardware keyboard.

## Out of scope

- Freehand-to-code generation.
- Mandatory stylus flows.
- Replacing the canonical program model.
- Reintroducing a permanent toolbox rail.
- Provider-backed AI behavior.
