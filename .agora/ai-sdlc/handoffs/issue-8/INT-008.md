# Product intent

## Business outcome

Turn the Product Intent into an implementable learner journey for the POC: define the POC learner journey and editor information architecture in a single actionable document, `docs/product/LEARNER_JOURNEY.md`, covering mission entry, editor first load, visual programming, continuous code observation, run/fail/iterate, help/tutor, mission completion, and reflection/free play, including the mandatory dual-surface layout decision.

## Users and stakeholders

Learners (POC target ~8-14 years old, no required prior experience; usable by older beginners), the implementation team (must build navigation/layout without guessing), and the Product Owner who owns all scope/acceptance judgement. Source facts: `docs/product/PRODUCT_INTENT.md`, `docs/product/MVP.md`, `docs/product/PEDAGOGY.md`, repository `AGENTS.md`.

## Scope and non-goals

In scope: the learner journey and editor information architecture document, including split/layout ratios, narrow-viewport behavior, block↔code selection relationship, mission/tutor placement, Run/Stop/Reset and save/exit behavior. Out of scope: React component implementation (issue #8 "Agent handoff"), accounts, public sharing, mission catalog UI, and the non-goals listed in `PRODUCT_INTENT.md`.

## Success measures

Issue #8 acceptance criteria: every POC screen/state has a purpose; code panel continuously visible on the main editor path; happy path and stuck path documented; no account/public-sharing flow; implementation team can build navigation/layout without guessing; narrow-viewport degradation identified. Verification: independent product review against `PRODUCT_INTENT.md` and `MVP.md`.

## Risks and dependencies

Depends on the three product documents, `AGENTS.md`, and the dual-surface invariant in `docs/architecture/SYSTEM_DESIGN.md` / `docs/architecture/AI_TUTOR.md`. Risks: over- vs under-specification tension against the "no guessing" acceptance; the pre-existing un-governed draft at `docs/product/LEARNER_JOURNEY.md` must stay non-authoritative until approved; durable Agora decision recording is pending (agora-ai-sdlc #155), so confirmed decisions are not auditable approval evidence until the Product Owner approves.
