# Product intent

## Business outcome

Rewrite the durable product and pedagogy source of truth so Agorix is explicitly an open-source, AI-native programming learning environment for children. The product definition must move from "block editor with optional tutor help" to a visible learner loop where AI can propose, the child decides, the runtime proves behavior, and the child explains what changed.

## Users and stakeholders

- Child learners, primarily ages 8-14, who should retain authorship and agency while learning programming.
- Parents, educators and reviewers who need to understand why Agorix is different from Scratch plus a chatbot.
- Implementation agents for issues #70-#72 and later architecture work; they must inherit clear product invariants before implementing.
- Product Owner and independent reviewers who own acceptance, unresolved decisions and delivery ordering.

## Scope and non-goals

In scope: update `docs/product/PRODUCT_INTENT.md`, `docs/product/PEDAGOGY.md` and `docs/product/LEARNER_JOURNEY.md`; revise `docs/product/CONTENT_GUIDE.md` only where terminology must shift from narrow tutor language to the broader learning-companion model.

Out of scope: product UI implementation, code architecture changes, provider selection, hidden LLM execution paths, mission completion by LLM judgment, or replacing deterministic runtime evidence with model claims.

## Success measures

Issue #69 acceptance is satisfied when the source documents define AI as transparent scaffolding in the learner loop, encode learner agency as testable product behavior, preserve deterministic runtime authority, prohibit invisible AI-originated program mutation, include explanation/reflection, align terminology across the three source-of-truth documents, and record unresolved decisions explicitly.

## Risks and dependencies

This work depends on the existing README, product documents, `docs/architecture/AI_TUTOR.md`, `AGENTS.md`, parent issue #63 and the operational order in #106. The main risk is over-correcting from "optional tutor" into an AI-driven product that weakens learner authorship; the counter-risk is preserving too much tutor-only language and leaving later architecture agents with ambiguous invariants.
