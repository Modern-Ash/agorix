## Functional Requirements

- FR-001: Create `docs/product/DESIGN_SYSTEM.md`.
- FR-002: Define reusable design tokens for Web/Tablet and Studio.
- FR-003: Define semantic color roles for movement, control/logic, data, events, AI proposal, runtime/execution, success, warning and error/debug.
- FR-004: Define typography scale, spacing/grid, radii, elevation, motion, iconography and focus/accessibility states.
- FR-005: Define light and dark surface rules.
- FR-006: Specify visual guidance for the required #117 components.
- FR-007: Include mockups/wireframes or screenshot-equivalent source-controlled examples for tablet landscape, tablet portrait and Studio dark IDE surface.
- FR-008: Document EN/ES text expansion behavior.
- FR-009: Document touch target guidance and no-hover-essential interaction expectations.
- FR-010: Make the system implementable without private design context.

## Explicit Anti-requirements

- AR-001: Do not make heavy black 2px borders and offset shadows the default visual identity.
- AR-002: Do not make Scratch-like puzzle-piece visual grammar the dominant identity.
- AR-003: Do not use permanent rainbow block palettes as primary decoration.
- AR-004: Do not require private Figma files for implementation.
- AR-005: Do not implement the Web shell in this issue.
