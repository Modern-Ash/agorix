## Risk Register

- R-001: The design system becomes subjective mood-board language instead of implementable rules.
  - Mitigation: require concrete tokens, component guidance and acceptance trace.

- R-002: The new visual language breaks continuity with current POC capabilities.
  - Mitigation: map required existing/future surfaces explicitly: world, code, proposals, runtime evidence and Learning Companion.

- R-003: Dark Studio and light Web diverge into separate products.
  - Mitigation: share semantic tokens and only vary surfaces/contrast.

- R-004: Accessibility is treated as polish.
  - Mitigation: make focus, contrast, non-color-only state, target size and reduced motion explicit design rules.

- R-005: Spanish copy expansion is forgotten by visual examples.
  - Mitigation: include EN/ES expansion guidance and long-label component behavior.

- R-006: Issue scope drifts into #118/#119/#120 implementation.
  - Mitigation: deliver documentation and examples only; leave app shell/touch/Worlds implementation to child issues.
