## Level 1 Plan

1. Establish visual principles
   - Translate #117 direction and anti-goals into concrete visual principles.
   - Distinguish Agorix from Scratch and from the current heavy-border POC style.

2. Define design tokens
   - Specify color, typography, spacing, grid, radius, elevation, motion and iconography tokens.
   - Include reusable light and dark token sets suitable for Web/Tablet and Studio.

3. Define semantic color and state model
   - Map movement, control/logic, data, events, AI proposal, runtime/execution, success, warning and error/debug to semantic roles.
   - Keep block/category color semantic and secondary, not the dominant brand identity.

4. Specify core components
   - Cover app shell, mission header, world surface, code surface, action palette, visual instruction/card, ProgramProposal card, diff proposal, Learning Companion prompt, execution state bubble, execution inspector row, progress indicator and touch controls.

5. Document accessibility and multilingual constraints
   - Include contrast, non-color-only state, visible focus, target sizes, reduced motion and EN/ES text expansion requirements.

6. Provide reviewable examples
   - Include source-controlled mockups/wireframes for tablet landscape, tablet portrait and Studio dark IDE surface.

7. Verify documentation completeness
   - Check that every #117 deliverable and acceptance criterion maps to a section in `DESIGN_SYSTEM.md`.
