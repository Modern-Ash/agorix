## Intent interpretation

Deliver GitHub issue #110 as a product i18n/l10n foundation for Agorix. Children must be able to use the learner UI, First Mission curriculum, feedback, proposal review, execution evidence, and Learning Companion in English or Spanish without changing program semantics, canonical hashes, or future programming language projection decisions.

The intent is not a text-only translation pass. The implementation must create a durable localization architecture with explicit locale registry, fallback behavior, catalog validation, tests, documentation, and evidence that the same canonical learner state survives locale switching.

## Scope boundaries

- In scope: English and Spanish product locales, app-level selection, localized current learner journey, First Mission, curriculum feedback and hints, deterministic Learning Companion responses, provider request locale propagation, safety-critical learner copy, README equivalence, contributor translation guidance, and automated tests.
- In scope as architecture contracts: future Studio/Worlds surfaces and future third locale addition.
- Out of scope: changing canonical programming language semantics, translating persisted code/AST/state, localizing internal machine-readable structured fields, and implementing full Studio/Worlds screens that do not yet exist.

## Proposed decision

Use a mature message-catalog approach with an ADR before construction. The default recommendation for this React/Vite product slice is FormatJS/react-intl because ICU messages and catalog validation fit pluralization, fallback, and future locales better than an ad hoc helper. If construction finds a strong repository constraint against that dependency, record the tradeoff in the ADR and keep the same public i18n contracts.
