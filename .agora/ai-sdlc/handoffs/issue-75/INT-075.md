# INT-075: Structured proposal review boundary

## Intent interpretation

Issue #75 implements the first concrete boundary that makes AI-originated program changes provisional, reviewable and unable to mutate canonical state invisibly.

The implementation should convert the existing Studio-local `ProgramProposal` idea into a shared Web/Tablet/Studio domain capability.

## Source facts

- #74 defines ProgramProposal as provisional state and requires canonical mutation only after learner accept/modify.
- #75 requires proposal id/version, proposed canonical patch/operation, affected node ids, rationale, deterministic validation, preview, explicit decision, and audit/event record without PII.
- #87 is still open; therefore #75 should implement a bounded initial protocol compatible with #87 rather than wait for #87.
- `extensions/vscode/src/studioCore.ts` already has a minimal `ProgramProposal` and `ProposalReview`, but it currently carries a full `proposedProgram` and lives only in Studio.
- `@agorix/program-model` owns canonical validation.
- `@agorix/code-generator` owns node-to-text mapping used for affected ranges.
- `@agorix/persistence` exposes semantic hash helpers that can support stale proposal checks.

## Proposed construction decision

Create a shared proposal package or shared domain module, preferably `packages/proposals`, with a small v1 protocol and pure helpers. Web/Tablet and Studio should consume the same fixtures and decision semantics.
